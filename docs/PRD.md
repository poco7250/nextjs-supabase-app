# 모임 이벤트 관리 웹 MVP PRD

## 🎯 핵심 정보

**목적**: 수영·헬스·친구 모임의 주최자가 단톡방/엑셀/계좌번호 복붙으로 반복하던 공지·참여자 관리·카풀·정산을, 초대 링크 하나로 시작해 한 화면에서 처리하도록 만든다.
**사용자**: 정기 모임(운동/친목)을 반복 운영하는 주최자와, 카톡 초대 링크로 들어와 간편 로그인 후 참여 여부와 정산을 처리하는 참여자.

## 🚶 사용자 여정

```
[비로그인 진입]
1. 진입 경로 분기
   ↓ 초대 링크로 진입한 경우                  ↓ 직접 방문
   초대 수락 페이지 (비로그인도 그룹 미리보기)   랜딩 페이지 → 로그인/회원가입 버튼
   ↓ "그룹 가입하기" 클릭
   [로그인 상태] → 즉시 가입 처리 → 그룹 홈 페이지
   [비로그인]   → 로그인 페이지 (초대 토큰 유지)

2. 로그인 페이지 / 회원가입 페이지
   ↓ 이메일 또는 구글/카카오 로그인 성공

   [초대 링크를 통해 온 경우] → 초대 수락 페이지로 복귀 → 그룹 가입 처리 → 그룹 홈 페이지
   [직접 방문한 경우]        → 대시보드(내 그룹 목록) 페이지
   ↓

3. 대시보드(내 그룹 목록) 페이지
   ↓ 그룹 선택                        ↓ 새 그룹 만들기
   그룹 홈 페이지                      그룹 생성 페이지 → 그룹 홈 페이지

4. 그룹 홈 페이지 (그룹 공지 + 예정 이벤트 목록)
   ↓ 이벤트 선택                ↓ 이벤트 만들기(주최자)         ↓ 설정/멤버 메뉴(주최자)
   이벤트 상세 페이지            이벤트 생성 페이지               그룹 설정 페이지 / 멤버 관리 페이지
                                 ↓ 생성 완료
                                 이벤트 상세 페이지

5. 이벤트 상세 페이지 (RSVP, 이벤트 공지, 출석 체크)
   ↓ RSVP 응답 (참석/불참/미정)
   [정원 초과] → 대기자 등록 → 자리 발생 시 자동 승급
   ↓ 카풀 메뉴 선택 (참석 확정자만)    ↓ 정산 메뉴 선택
   카풀 페이지                        정산 페이지

6. 카풀 페이지 → 운전자 등록 또는 탑승 신청/취소 → 이벤트 상세 페이지로 복귀
   정산 페이지 → 비용 항목 등록 → 자동 분담 계산 → 송금 완료/확인 처리 → 이벤트 상세 페이지로 복귀

7. 내 프로필 페이지 (공통 메뉴에서 언제든 진입) → 계좌 정보(은행/계좌번호/토스링크) 등록
   ↓ 로그아웃 → 랜딩 페이지
```

## ⚡ 기능 명세

### 1. MVP 핵심 기능

| ID       | 기능명                        | 설명                                                                                       | MVP 필수 이유                                 | 관련 페이지                        |
| -------- | ----------------------------- | ------------------------------------------------------------------------------------------ | --------------------------------------------- | ---------------------------------- |
| **F001** | 그룹 생성/수정                | 그룹명, 설명을 입력해 그룹을 만들고 이후 수정                                              | 반복 모임을 담는 최상위 단위                  | 그룹 생성 페이지, 그룹 설정 페이지 |
| **F002** | 초대 링크 발급/재발급         | 토큰 기반 초대 링크를 만들고 필요 시 재발급                                                | 카톡 공유 한 번으로 참여자를 모으는 핵심 흐름 | 그룹 설정 페이지                   |
| **F003** | 초대 링크로 그룹 가입         | 초대 링크 접속 → 그룹 미리보기(비로그인 허용) → 로그인 → 그룹 멤버로 등록                  | "링크 하나로 참여" 핵심 가치                  | 초대 수락 페이지                   |
| **F004** | 멤버 역할 관리                | owner/admin/member 역할 지정 및 변경                                                       | 주최자 위임 및 권한 분리                      | 멤버 관리 페이지                   |
| **F005** | 멤버 목록 조회/내보내기       | 그룹 멤버 목록 확인, 특정 멤버 내보내기(과거 이벤트·정산 기록은 보존)                      | 멤버 관리의 최소 기능                         | 멤버 관리 페이지                   |
| **F006** | 이벤트 생성(이전 이벤트 복제) | 일시/장소/설명/정원/응답마감 입력, 이전 이벤트 복제로 반복 생성                            | RRULE 없이 반복 모임을 단순하게 재현          | 이벤트 생성 페이지                 |
| **F007** | 이벤트 상태 관리              | 예정/마감/완료/취소 상태 표시 및 주최자 수동 변경(자동 전환 없음)                          | 참여자에게 현재 진행 상태를 알림              | 그룹 홈 페이지, 이벤트 상세 페이지 |
| **F008** | 공지 작성 및 상단 고정        | 그룹 단위·이벤트 단위 공지 작성, 상단 고정                                                 | 단톡방 공지를 대체하는 핵심 소통 채널         | 그룹 홈 페이지, 이벤트 상세 페이지 |
| **F009** | RSVP 응답                     | 참석/불참/미정 응답 등록 및 변경                                                           | 참여자 관리의 핵심 입력                       | 이벤트 상세 페이지                 |
| **F010** | 정원 초과 대기자 관리         | 정원 초과 시 대기열 등록, 자리 발생 시 대기 등록 순서대로 자동 승급                        | 인원 관리 자동화                              | 이벤트 상세 페이지                 |
| **F011** | 출석 체크                     | 주최자가 참석자 출석 여부 체크                                                             | 실제 참여 확인                                | 이벤트 상세 페이지                 |
| **F012** | 카풀 등록(운전자)             | 출발지/출발시간/좌석 수 등록                                                               | 카풀 조율을 단톡방 대신 시스템으로            | 카풀 페이지                        |
| **F013** | 카풀 신청/취소(탑승자)        | 등록된 카풀에 신청/취소(선착순), 잔여 좌석 표시                                            | 자율 신청형 카풀의 핵심 동작                  | 카풀 페이지                        |
| **F014** | 비용 항목 등록 및 N빵 계산    | 항목별 이름/금액/결제자/분담자 지정, 자동 분담 계산(원단위 나머지는 결제자 부담)           | 정산 계산 자동화 핵심 가치                    | 정산 페이지                        |
| **F015** | 정산 요약 및 송금 확인        | 사람별 "누구에게 얼마" 요약(두 사람 간 차액 상계), 계좌/토스 링크 표시, 송금완료/확인 처리 | 실결제 없이 정산을 마무리하는 핵심 흐름       | 정산 페이지                        |

### 2. MVP 필수 지원 기능

| ID       | 기능명                   | 설명                                                                               | MVP 필수 이유                       | 관련 페이지                    |
| -------- | ------------------------ | ---------------------------------------------------------------------------------- | ----------------------------------- | ------------------------------ |
| **F020** | 기본 인증                | 이메일 회원가입/로그인, 구글 로그인, 카카오 로그인(이메일 동의 필수), 로그아웃     | 초대 링크 참여를 위한 최소 인증     | 로그인 페이지, 회원가입 페이지 |
| **F021** | 프로필 및 계좌 정보 관리 | 표시 이름, 은행명, 계좌번호, 토스 송금 링크 등록/수정(계좌는 정산 상대에게만 노출) | 정산 기능에 직접 필요한 최소 데이터 | 내 프로필 페이지               |
| **F022** | 내 그룹 목록 조회        | 소속 그룹 목록과 각 그룹의 다음 이벤트 요약 표시                                   | 로그인 후 진입점                    | 대시보드(내 그룹 목록) 페이지  |

### 3. MVP 이후 기능 (제외)

- 실결제/PG 연동 (계좌 송금은 사용자가 직접 처리)
- 푸시 알림, 카카오 알림톡 연동
- RRULE 기반 정교한 반복 이벤트
- 그룹/이벤트 내 채팅
- 경로 기반 자동 카풀 매칭
- 3인 이상 순환 상계(A→B→C→A 송금 건수 최소화)
- 이벤트 상태 자동 전환(마감 시각 도달 시 자동 마감 등)
- 회비 장부(월회비, 누적 잔액 관리)
- 프로필 상세 관리(아바타, 자기소개), 알림 설정 등 일반 Nice-to-have

## 📄 페이지별 상세 기능

### 랜딩 페이지

> **구현 기능:** 없음 (서비스 소개 전용) | **메뉴 위치:** 비로그인 홈

| 항목            | 내용                                                                         |
| --------------- | ---------------------------------------------------------------------------- |
| **역할**        | 비로그인 사용자에게 서비스를 소개하고 로그인/회원가입으로 유도하는 진입 화면 |
| **진입 경로**   | 앱 최초 방문, 또는 로그아웃 직후                                             |
| **사용자 행동** | 서비스 소개 확인, 로그인/회원가입 버튼 클릭                                  |
| **주요 기능**   | • 서비스 소개 카피<br>• **로그인** 버튼<br>• **회원가입** 버튼               |
| **다음 이동**   | 로그인 버튼 → 로그인 페이지, 회원가입 버튼 → 회원가입 페이지                 |

## 📐 데이터 규칙 및 제약

### 값 제약 (CHECK)

- `group_members.role`: `owner` / `admin` / `member`
- `events.status`: `scheduled` / `closed` / `completed` / `canceled` (예정/마감/완료/취소, 주최자 수동 변경만)
- `event_rsvps.status`: `going` / `not_going` / `maybe` / `waitlisted`
- `carpool_riders.status`: `requested` / `canceled`
- 금액(`amount`, `share_amount`)은 원 단위 정수. 일반 항목은 0 이상, `is_adjustment = true`인 조정 항목만 음수 허용. `seat_count`와 `capacity`는 1 이상

### 유니크 제약

- `group_members(group_id, user_id)`, `event_rsvps(event_id, user_id)`, `expense_shares(expense_id, user_id)`
- `carpool_riders(carpool_id, rider_id) where status = 'requested'` (부분 유니크)
- `carpools(event_id, driver_id)` (이벤트당 운전자 1회 등록)
- `group_invites(group_id) where revoked_at is null` (그룹당 활성 초대 1개, 재발급 시 기존 토큰에 `revoked_at` 기록)
- `group_invites(token)`, `settlement_transfers(event_id, from_user_id, to_user_id)`

### 동시성 처리

- RSVP 참석 응답, 불참 전환에 따른 대기자 승급, 카풀 탑승 신청은 모두 Postgres 함수(RPC) 안에서 처리한다. 대상 `events` / `carpools` 행을 `select ... for update`로 잠근 뒤 정원·잔여 좌석을 확인하고 한 트랜잭션으로 반영한다.
- 대기자 승급은 `waitlisted_at` 오름차순(선착순).
- 함수는 기존 패턴대로 `security definer` + `set search_path = ''`로 만들고, 내부에서 `auth.uid()`로 권한을 확인한다.

### 정산 계산 규칙

1. 항목별 분배: 결제자가 아닌 분담자에게는 `floor(amount / 분담자 수)`만 청구하고, 나머지 원 단위는 결제자가 부담한다. 예) 10,000원 ÷ 3명 → 3,333원씩 청구, 1원은 결제자 부담.
2. 결제자도 분담자에 포함될 수 있다. 이 경우 본인 몫은 송금 대상이 아니다(자기 자신에게 송금하는 행 없음).
3. 이벤트 단위로 (송금자, 결제자) 쌍별 금액을 합산하고, 두 사람 사이에 반대 방향 금액이 있으면 차액만 남긴다. 3인 이상 순환 상계는 하지 않는다.
4. `settlement_transfers`는 비용 항목이 바뀔 때마다 재계산한다. 이때 `transfer_marked_at`(송금 완료 표시)만 있는 건은 금액이 바뀌면 표시를 초기화한다.
5. `confirmed_at`(입금 확인)이 하나라도 있는 이벤트는 기존 비용 항목 수정·삭제를 막고, 음수 금액을 허용하는 **조정 항목**을 추가하는 방식으로만 정정한다.

### 접근 권한 (RLS)

- 그룹·이벤트·공지·카풀·정산 데이터는 해당 그룹 멤버만 조회한다. 생성·수정은 역할에 따라 제한한다(이벤트·공지·멤버 관리는 owner/admin).
- 반복되는 권한 체크는 `is_group_member(group_id)`, `is_group_admin(group_id)` 헬퍼 함수로 만들어 정책에서 재사용하고, `group_members(group_id, user_id)`, `event_rsvps(event_id, user_id)` 유니크 인덱스를 조회 인덱스로 쓴다.
- 카풀·정산 페이지는 해당 이벤트 참석(`going`) 응답자만 이용한다.
- 초대 미리보기: 비로그인 사용자는 토큰으로 그룹명·설명만 돌려주는 security definer RPC(`get_invite_preview(token)`)로 조회한다. 초대 수락 페이지 경로를 `lib/supabase/proxy.ts`의 공개 경로 목록에 추가해야 한다.
- 계좌 정보: `payment_accounts` 참고.
- 멤버 내보내기는 `group_members` 행만 삭제하고, 과거 RSVP·카풀·비용·정산 기록은 이력으로 보존한다(표시 이름은 "나간 멤버"로 표기).

### 외부 의존성

- 카카오 로그인은 이메일 동의항목을 필수로 받는다. 이 항목은 카카오 **비즈 앱** 전환 심사를 통과해야 요청할 수 있으므로, 개발 착수와 동시에 심사를 신청한다. 심사 완료 전까지는 이메일·구글 로그인만 노출한다.
